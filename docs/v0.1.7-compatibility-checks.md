# v0.1.7 compatibility and release checks

## Changes

- Claude hook installation repairs old app paths and incomplete event sets while
  retaining other handlers and settings. Invalid configuration is not overwritten.
- Child-scoped Claude events cannot replace or delete main-session state.
  Current `notification_type` payloads take priority over the older matcher argument.
- Codex rollout detection includes ChatGPT handoffs and known older root sources;
  Guardian and subagent rollouts remain excluded.
- Readers and installers share `CODEX_HOME` / `CLAUDE_CONFIG_DIR` resolution.
  GUI launches must inherit these environment variables to use custom roots.
- Onboarding shows the effective Claude settings path; About links to the correct repository.
- Optional Codex hooks observe start, prompt, tool, permission, completion,
  interruption and session-end events. The helper returns `{}` and makes no
  permission decision. Payload prompts and tool arguments are not persisted.
- Codex hook completion markers survive source merging, deduplicate notifications,
  and distinguish interruption/disappearance from completion before the first Stop.

## Limits

Codex hooks require a supported runtime (use 0.169 or later). Upgrade older CLI
versions sharing the same Codex home before installation, then review and trust
the exact definitions in Settings > Hooks or `/hooks`. Agent Light never grants
trust and cannot verify it. The local CLI is 0.137; its hook integration was not
enabled or claimed as tested. Rollout detection remains the default fallback.

Synthetic helper/collector tests do not prove live provider hook delivery or OS
notification delivery. A clean-user installation, Intel, offline first launch and
login-item startup after re-login remain outside this check.
The successful local upgrade/launch does not promise the absence of ordinary
download, notification or login-item prompts on every Mac.
